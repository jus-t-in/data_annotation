## 3. 原始信号与坐标口径

### 3.1 CSV 字段

| 参数 | 字段 | 本次用途 |
|---|---|---|
| 相对时间 | `Elapsed (s)` | 计算持续时间、频率和事件顺序；最终边界吸附到该列的真实采样点 |
| 右腿位置 | `左右腿位置/右腿位置` | 右腿摆动、落地、步频、腿部静止和动作幅度 |
| 左腿位置 | `左右腿位置/左腿位置` | 左腿摆动、落地、步频、腿部静止和动作幅度 |
| 三轴加速度 | `Accelerometer/Accelerometer X/Y/Z` | 落脚冲击、整体动态强度、重力方向和垂直加速度 |
| 三轴角速度 | `Gyroscope/Gyro X/Y/Z` | 动作起止、局部静止、转身和姿态变化速度 |
| 俯仰 | `俯仰与侧倾/俯仰` | 弯腰、蹲起阶段、楼梯或坡面姿态带及其迁移 |
| 侧倾 | `俯仰与侧倾/侧倾` | 左右重心变化、转身和上下设备时的辅助证据 |

### 3.2 IMU 到人体坐标系

`imu_to_body_transform.yaml` 定义：

```text
x：向左
y：向下
z：向后
v_human = R_human_from_imu * v_imu
R_human_from_imu = I
```

因此本批加速度和角速度无需换轴或变号，直接按 CSV 的 `X/Y/Z` 使用。角速度正方向遵循右手定则。若以后改变安装方向，必须先应用新的变换矩阵，不能继续沿用本文关于某一轴正负方向的经验。

俯仰和侧倾是设备已经计算出的姿态量，不经过上述三轴向量变换。本次主要使用它们的相对变化、区间中位数和变化方向，而不是绝对角度。

## 4. 标注总体流程

本次没有调用自动标注工具生成答案，而是按以下顺序联合检查 CSV：

1. 检查字段、有限数值、时间单调性、采样率、重复时刻和数据断档。
2. 绘制每个试次的全局信号图，先确认完整动作组和长时间状态段。
3. 对候选边界绘制局部放大图，同时查看双腿位置、俯仰、侧倾、三轴角速度和三轴加速度。
4. 先判活动是否真实发生，再判承重地形；协议顺序只作完整性复核。
5. 对蹲起、楼梯和跑步机换场等复杂边界，要求至少两类信号相互支持。
6. 将普通边界吸附到最近的真实 `Elapsed (s)` 采样点；同一时刻的活动和地形变化合并为一个事件。
7. 单独复核相邻同状态事件，只保留楼梯第二步和试次收尾确认标记。
8. 最后检查标签集合、组合状态、时间严格递增和 T05 条件备注。

T04 是混合留出试次。本次先独立完成其他试次的判断，再检查 T04；没有根据 T04 反向修改阈值或分类规则。

## 5. 建议派生的检测特征

人工观察的是原始曲线，但算法应使用时间归一、抗噪且可解释的派生特征。以下特征覆盖了本次实际用到的证据。

### 5.1 腿位特征

设右腿、左腿位置分别为 `R(t)`、`L(t)`：

```text
v_R(t) = dR/dt
v_L(t) = dL/dt
leg_speed(t) = sqrt(v_R(t)^2 + v_L(t)^2)
span_R = P95(R) - P5(R)
span_L = P95(L) - P5(L)
```

建议计算：

- 平滑后的腿位和腿速，平滑只去除采样抖动，不应抹掉摆腿起点。
- 每条腿的峰、谷、显著度、峰宽和摆动起点。
- 相邻同侧峰或落地点的周期、左右交替次数、步频稳定性。
- 双腿速度相关系数和相位差。
- 单腿主导度，例如 `max(N_R, N_L) / (N_R + N_L)`。

本数据约定中，右腿抬动通常表现为正向峰，左腿抬动通常表现为负向峰。因此检测峰时可先使用 `R` 和 `-L` 统一抬腿方向。该符号必须在每种设备或佩戴方式的第一段清晰步态上验证，不能无条件硬编码。

原始双腿通道的符号约定不同，物理上同步的蹲起可能在原始速度上呈负相关。算法应同时保存原始相关系数和“统一物理方向后”的相关系数，避免把符号约定误认为动作相位。

### 5.2 角速度特征

建议至少计算两种运动强度：

```text
gyro_motion = norm(gyro - slow_lowpass(gyro))
gyro_local_rms = sqrt(sum(E[g_i^2] - E[g_i]^2))
```

- `gyro_motion` 适合找较长动作段的开始和结束。
- `gyro_local_rms` 适合判断某个短窗口是否真正安静。
- 平滑后的 `Gyro Y` 在当前安装方向下对原地转身较敏感。
- 三轴角速度共同回落比单轴过零更适合确认静止，因为动作换向也会短暂过零。

窗口应按秒定义。仓库旧离线规则使用约 `1.0 s` 的慢基线和约 `0.2 s` 的局部统计窗，可作为初始搜索范围，不应按固定样本数复制到不同采样率的数据。

### 5.3 加速度与落脚冲击

先计算：

```text
a_mag = norm([a_x, a_y, a_z])
impact = smooth(abs(a_mag - slow_lowpass(a_mag)))
```

`impact` 用来检查落脚、楼梯核心区和地形边界。它应采用“相对同一试次平地基线”的比例，而不是跨设备绝对阈值。

还可以估计重力方向并提取竖直线性加速度：

```text
gravity = long_lowpass(accel)
a_up = (dot(accel, gravity / norm(gravity)) - norm(gravity)) * 9.80665

vertical_rms = RMS(a_up)
vertical_asymmetry = P95(a_up) / abs(P5(a_up))
```

`vertical_rms` 表示步态竖直冲击强度，`vertical_asymmetry` 可辅助区分上楼蹬伸与下楼落脚。重力估计窗口应明显长于步态周期。仓库旧规则使用约 `8 s` 的重力窗和约 `3 s` 的特征窗，适合离线分析；实时算法需要使用因果滤波并接受额外检测延迟。

上式假定 CSV 加速度已经按 `g` 归一化；若设备输出单位是 `m/s²`，应去掉 `9.80665`，并在所有阈值中保持单位一致。

### 5.4 俯仰和侧倾

建议计算：

- 俯仰、侧倾的平滑值和一阶导数。
- 区间中位数、`P95-P5` 摆幅及相对静止基线的偏移。
- 俯仰带的持续性穿越，而不是一次瞬时越阈。
- 侧倾摆幅与腿位相位，用于判断左右承重转移和上下设备动作。

俯仰是弯腰和地形判定的重要信号，但绝对角度受佩戴初始姿态影响。楼梯、跑步机坡度和动作姿态应优先使用“相对同试次基线的变化”，不能直接规定某个绝对角度就是上楼或上坡。

## 6. 证据优先级和判定顺序

本次标注采用以下证据优先级：

1. 双腿是否形成明确、持续的运动模式。
2. 角速度和加速度是否支持动作开始、停止或冲击变化。
3. 俯仰和侧倾是否支持躯干姿态或地形带迁移。
4. 多个信号的时间关系是否符合候选动作。
5. 试次协议是否与已观察到的动作数量、顺序大致一致。

协议不能覆盖前四项。例如 T04 计划要求一次“无最低位停顿半蹲”，但 CSV 出现约 `2.1 s` 的低位平台，因此仍标为 `SQUAT_HOLD`。T01 文件开头也没有按协议强制标成静止，而是根据实际运动标成 `OTHER`。

建议算法采用“候选状态 -> 持续性确认 -> 输出状态”的结构，并为进入和退出使用不同阈值。单个峰、单次过零或一次冲击只能建立候选，不能直接切换状态。

## 7. 活动标签的参数依据

### 7.1 `STILL`

主要证据：

- `leg_speed` 持续降到该试次静止噪声范围，双腿位置形成平台。
- `gyro_local_rms` 明显回落，三轴角速度只剩小幅平衡晃动。
- 加速度冲击残差回落，不再出现周期性落脚冲击。
- 俯仰和侧倾保持在局部稳定带内。

边界取当前动作实际停止的位置，而不是某一通道恰好过零的位置。动作换向也会使瞬时速度接近零，必须要求低运动证据持续一段时间。

需要特别区分：

- 楼梯中途并脚停止仍是 `STILL`，但地形保持 `ASCENT` 或 `DESCENT`。
- 正坡度跑步机调坡时，若人仍站在随设备抬升的边缘上，是 `STILL · INCLINE`。
- 蹲在最低位保持不是 `STILL`，而是 `SQUAT_HOLD`。
- 轻微维持平衡的晃动仍可属于 `STILL`。

8.3 的 T02 四次楼梯停顿分别约为 `0.98 s`、`2.31 s`、`2.30 s` 和 `3.39 s`。这些区间同时出现腿位平台、角速度回落和加速度稳定，因此按实际时长标注，没有按协议目标时长改写。

### 7.2 `WALKING`

主要证据：

- 左右腿峰谷持续交替，至少形成多个连续摆腿周期。
- 两条腿都有有效摆幅，不是单腿反复抖动。
- 同侧周期和左右步间隔在一个局部窗口内相对稳定。
- 角速度和加速度呈与步频同步的周期性变化。
- 落脚附近常伴随加速度冲击，但冲击大小随速度、鞋和地形变化。

开始边界取第一只脚开始形成持续交替步态的摆动起点，停止边界取最后一段连续步态结束后双腿和 IMU 真正安静的位置。自然转身、平台步态和跑步机行走仍属于 `WALKING`。

与相邻类别的区别：

- 对比 `HIGH_KNEE_ALTERNATING`：高抬腿通常摆幅和峰显著度更大，躯干没有连续前进步态的姿态及冲击模式。
- 对比 `STANDING_ADJUSTMENT`：站立调整缺少稳定、持续的双腿交替周期，常表现为单侧、小幅或不规则运动。
- 对比 `OTHER`：上下设备虽可出现数步，但伴随扶持、明显侧倾或非稳定步态，不应仅因出现腿峰就标成行走。

### 7.3 `BEND`

主要证据：

- 俯仰出现显著、连续的前屈再恢复波形，完整覆盖从直立到前倾再回直立。
- 俯仰摆幅明显大于同一受试者的普通站立调整和蹲起姿态变化。
- 角速度支持躯干前屈和回正的两个方向阶段。
- 双腿没有形成交替步态；腿位变化只作为姿态联动证据。

边界从持续前屈开始，到恢复直立且运动停止。连续多次弯腰时，如果顶部停顿不足分段标准，可保留为一个完整动作组。

仓库历史开发集曾使用 `pitch PTP >= 30°` 作为弯腰候选起点，并观察到弯腰约 `38-42°`、深蹲约 `16-21°` 的分离。但其他受试者已经出现弯腰与深蹲俯仰摆幅重叠的案例，因此实际算法还必须加入腿位相位、膝部动作和角速度方向，不能只看俯仰幅度。

### 7.4 `SQUAT_DESCENT`

主要证据：

- 两腿位置按蹲下的身体运动同步改变；由于原始通道符号相反，原始速度相关系数可能显著为负。
- 俯仰和角速度出现持续下降阶段，而不是一次短小屈膝。
- 双腿不是左右交替峰，峰率通常低于步态。
- 动作从直立基线持续远离，形成明确的身体降低过程。

边界从直立状态开始持续下降时开始，到最低点换向或下降停止时结束。轻微屈膝、重心调整或抖腿不形成持续身体下降，不应标为下蹲。

### 7.5 `SQUAT_HOLD`

主要证据：

- 前一状态是明确的 `SQUAT_DESCENT`。
- 双腿位置停在最低位平台，`leg_speed`、角速度和俯仰速度共同回落。
- 低位平台持续达到 `0.5 s`。
- 姿态仍明显偏离直立基线，所以不能标为 `STILL`。

确认保持达到 `0.5 s` 后，边界应回标到下降实际停止的采样点，而不是标在 `0.5 s` 确认完成的时刻。T04 半蹲的低位平台约为 `45.941-48.035 s`，持续约 `2.09 s`，是“实际证据优先于计划”的典型例子。

### 7.6 `SQUAT_ASCENT`

主要证据：

- 双腿位置和俯仰从最低位开始沿与下降相反的方向持续恢复。
- 角速度方向随上升发生稳定改变。
- 从最低点直接换向时，边界接在 `SQUAT_DESCENT` 后；存在保持时，接在 `SQUAT_HOLD` 后。

结束边界取回到直立且上升停止的位置。连续蹲起顶部停顿不足 `0.5 s` 时，直接切到下一次 `SQUAT_DESCENT`；达到 `0.5 s` 时，中间插入 `STILL`。

### 7.7 `HIGH_KNEE_ALTERNATING`

主要证据：

- 左右腿大幅、清晰、连续交替抬高。
- 两条腿都有较大的摆幅和峰显著度，单腿主导度不高。
- 峰序列规则，但没有平地或楼梯行走的持续前进型态。
- 俯仰基线通常比弯腰稳定；角速度和加速度呈原地高抬造成的周期冲击。

历史开发集曾以双腿最小摆幅约 `1.55`、峰显著度约 `1.40` 作为候选起点，而普通行走摆幅和显著度相对较小。这些均是设备原始单位，只适合做同设备的初始网格搜索。更稳健的实现应使用“相对该受试者普通步态摆幅的倍率”和双腿交替结构。

### 7.8 `STANDING_ADJUSTMENT`

该标签统一覆盖站立抖腿、原地转身和小幅拖步。主要证据：

- 运动强度高于静止噪声，但没有稳定的前进步态周期。
- 腿位常表现为单侧、小幅、间歇或不规则变化。
- 站立抖腿可有持续高频小幅往复，但另一条腿相对稳定。
- 原地转身常在平滑 `Gyro Y` 上出现明显正负峰，并伴随侧倾变化。
- 小幅拖步有腿位变化和落脚冲击，但摆幅、步数和连续性低于正常行走。

左右脚交换或从抖腿变成原地转身不产生新的主标签边界。内部真正停止达到 `0.5 s` 时切为 `STILL`，再次动作时再建立新的 `STANDING_ADJUSTMENT` 段。

历史开发集中的原地转身候选曾使用约 `1 s` 窗口的 `|Gyro Y| >= 25` 和动作时长不超过约 `3 s`。该数值依赖安装方向和设备单位，算法应先用静止及普通行走的 `Gyro Y` 分布做会话内归一化。

### 7.9 `OTHER`

主要证据是“可以确认发生了独立动作，但不符合任何专名标签”，而不是“不确定”。本批包括：

- T01 和 T05 文件开头已经处于明确调整动作中。
- T05 真实平地结束后的设备换场。
- 跑带、跑步机边缘和真实平地之间的跨步及站位调整。

`OTHER` 仍要求腿位、角速度、加速度或姿态中存在连贯动作证据。孤立毛刺、不确定小幅波动、传感器噪声和数据断档不能用 `OTHER` 掩盖。算法可以把“明确运动但命名类别分数都不足”作为 `OTHER` 候选，同时输出证据原因供复核。

## 8. 地形标签的参数依据

### 8.1 `LEVEL`

`LEVEL` 包括真实平地、楼梯平台和跑步机 `0°`。主要证据是：

- 行走时俯仰处于该试次的平地姿态带。
- 步频、腿位摆幅和落脚冲击恢复到该段平地模式。
- 静止时主要承重面已确认在真实平地或水平跑带。

`LEVEL` 不能仅由“没有检测到楼梯”得出。在 T05 换场中，如果没有看到上下设备或承重转移证据，应保留上一可确认地形，并将边界列为复核风险。

### 8.2 `ASCENT`

主要证据：

- 第一只脚开始摆向上楼第一级台阶，腿位摆幅和节奏由平地步态转入楼梯步态。
- 俯仰平滑值进入与平地不同的持续姿态带。
- 加速度冲击和竖直加速度结构相对平地发生变化。
- 后续另一只腿出现符合时间关系的第二步，可作为确认，但不再次切换状态。

进入边界取第一只脚“开始摆向台阶”的时刻，不等到触碰台阶；退出边界取最后一个楼梯周期结束并开始平台步态，或实际到达平台后停止的时刻。

上楼中途并脚停止时，活动切成 `STILL`，地形仍保持 `ASCENT`。恢复迈步时再切回 `WALKING · ASCENT`。

### 8.3 `DESCENT`

下降使用与上楼相同的多信号结构，但俯仰带方向、竖直冲击不对称和步频关系不同：

- 第一只脚开始摆向下楼第一级台阶建立进入候选。
- 俯仰进入下楼姿态带，但部分受试者的下楼与平地俯仰差可能很小。
- 下楼落脚冲击常比相邻平地更明显，可用相对冲击比辅助。
- 当下楼后的平地快走步频明显变快时，持续步间隔变化可辅助定位退出边界。

不能只用俯仰正负号区分 `ASCENT` 和 `DESCENT`。绝对符号受佩戴姿态影响，应先从清晰楼梯段建立会话内姿态带，再结合腿位起步、竖直加速度和冲击不对称判断方向。

### 8.4 `INCLINE`

V2 将跑步机 `10°`、`15°` 和 `25°` 都标为 `INCLINE`，角度只写入采集条件，不拆成地形类别。主要证据：

- 人在正坡度跑带上形成持续交替步态。
- 俯仰基线和周期波形相对 `0°` 跑步机发生稳定变化。
- 腿位周期、加速度和角速度确认是在持续行走，而不是边缘等待或跨步。
- 人站在随设备抬升的跑步机边缘等待调坡时保持 `STILL · INCLINE`。

本批 CSV 没有跑步机角度或速度遥测，具体 `10°/15°/25°` 依赖固定采集顺序。`0°` 采集时受试者在跑带上经历启动和加速；三个正坡度条件均在坡度和速度稳定后才从边缘跨回跑带，因此其行走段不含调坡或跑带变速。训练时应排除 `0°` 启动加速、跑带与边缘之间的跨步、边缘等待和证据不足部分。

本批正坡度换场可由腿位、角速度和侧倾辨认：离开连续步态后先跨到边缘，站稳并随设备调坡，再跨回运行中的跑带。跨步标为 `OTHER · INCLINE`，边缘等待标为 `STILL · INCLINE`；只有形成持续交替步态后才切回 `WALKING · INCLINE`。

## 9. 合法组合状态

| 地形 | 允许的活动 |
|---|---|
| `LEVEL` | 全部 V2 活动标签 |
| `ASCENT` | `WALKING`、`STILL` |
| `DESCENT` | `WALKING`、`STILL` |
| `INCLINE` | `WALKING`、`STILL`、T05 换场中的 `OTHER` |

建议算法先分别产生“活动候选”和“地形候选”，再经过组合状态约束和状态机输出最终状态。非法组合不应自动改成最接近的合法标签，而应保留候选证据并触发 QA。

## 10. 边界和确认事件

### 10.1 普通边界

- 每个试次首事件固定在首个真实采样点，用来声明初始状态。
- 普通事件必须改变活动或地形中的至少一项。
- 活动和地形同一时刻变化时合并成一条事件。
- 相邻同状态区间合并，不能按每个脚步重复切段。
- 最后一个状态持续到原始 CSV 结束。
- 离线分析可以回看边界两侧；实时算法不能回写过去，应把检测延迟和事件发生时刻分开记录。

### 10.2 楼梯第二步确认

楼梯进入后，另一条腿的下一次有效摆动可以作为“第二步确认”。它重复当前 `WALKING · ASCENT/DESCENT` 状态，不切分区间。历史规则曾在首步后约 `0.2-1.5 s` 搜索相反腿下一步，可作为候选范围；真正约束仍应来自当前步频。

### 10.3 T05 条件区间

T05 不设置固定步数、周期数或时长，也不生成 `STEADY_GAIT_START/END`。采集条件直接写在对应 `WALKING` 起始事件的备注中。8.3 的实际活动区间为：

| 条件 | `WALKING` 开始（s） | 退出连续步态（s） | 时长（s） |
|---|---:|---:|---:|
| 真实平地·自然速度 | 8.934 | 38.830 | 29.90 |
| 跑步机·0°·3 km/h | 53.158 | 101.791 | 48.63 |
| 跑步机·10°·3 km/h | 139.937 | 176.540 | 36.60 |
| 跑步机·15°·3 km/h | 198.796 | 236.087 | 37.29 |
| 跑步机·25°·3 km/h | 278.866 | 316.211 | 37.34 |

这些是活动真值区间，不是固定训练窗口。`0°` 区间开头包含跑带启动加速，训练导出时需排除；三个正坡度区间从完成跨入、形成持续交替步态开始，跨回边缘或下到地面时结束。

## 11. 五个试次的实际经验

### 11.1 T01：连续平地、上楼、平台、下楼

- 文件开头 `0-2.786 s` 有明确腿位和 IMU 调整，标为 `OTHER · LEVEL`。
- 三轮往返都由连续左右交替腿位确认。
- 楼梯进入重点看首腿摆动起点、俯仰带迁移和冲击变化。
- 楼梯退出重点看腿位型态恢复、平台步态或停止，而不是固定时长。

算法经验：同一个 `WALKING` 活动段内部可以连续发生 `LEVEL -> ASCENT -> LEVEL -> DESCENT -> LEVEL`，活动检测和地形检测必须解耦。

### 11.2 T02：楼梯中途停止

- 四次停止都有腿位平台、局部角速度回落和加速度稳定。
- 停止期间保持楼梯地形，形成 `STILL · ASCENT/DESCENT`。
- 恢复边界取重新出现持续摆腿的位置，不按目标停顿时长推算。

算法经验：运动门控不能在检测到静止后重置地形为 `LEVEL`；地形状态需要独立记忆。

### 11.3 T03：非目标动作和蹲起三阶段

- 弯腰由三次显著俯仰波形确认。
- 半蹲和深蹲都拆为下降、保持和上升，深度不形成新标签。
- 最低位达到 `0.5 s` 才建立 `SQUAT_HOLD`；顶部达到 `0.5 s` 才插入 `STILL`。
- 站立抖腿换脚不切段。
- 左右转之间实际停止达到 `0.5 s`，因此分成两个 `STANDING_ADJUSTMENT` 段。

算法经验：先检测运动方向和姿态平台，再组合成阶段标签，比识别“完整一次深蹲”更适合在线状态输出。

### 11.4 T04：混合留出

- 平地行走可直接切到站立抖腿，再直接恢复行走，中间不强制插入 `STILL`。
- 计划中的无保持半蹲实际有约 `2.09 s` 低位平台，按证据标为 `SQUAT_HOLD`。
- 最终楼梯边界由腿位、俯仰和步态连续性共同确定。

算法经验：T04 应只用于最终验收。只要根据其错误调整了阈值，就应把它移出留出集并另找独立测试数据。

### 11.5 T05：真实平地与固定坡度跑步机

- 真实平地和跑步机 `0°` 都属于 `LEVEL`。
- `10°/15°/25°` 都属于 `INCLINE`，角度通过受控备注区分。
- `0°` 行走结束后跨到边缘，并随设备抬升进入正坡度等待；`10°` 和 `15°` 行走结束后也跨到边缘等待下一次调坡。跨步为 `OTHER · INCLINE`，站稳等待为 `STILL · INCLINE`。
- 三个正坡度均在坡度与 `3 km/h` 速度稳定后跨回跑带；跨入过程结束并形成持续交替步态后才标为 `WALKING · INCLINE`。
- 最终在 `316.211 s` 离开连续步态并开始下设备，标为 `OTHER · INCLINE`；约 `320.504 s` 主要承重转到真实平地后切为 `OTHER · LEVEL`；`321.479 s` 下设备完成后切为 `STILL · LEVEL`。

算法经验：稳态地形分类和换场边界检测应分成两个问题。前者可以用数秒窗口统计俯仰、步态和竖直加速度；后者需要腿位、侧倾、扶持动作或设备遥测，难度更高。

## 12. 数值阈值应怎样使用

### 12.1 规范定义的硬条件

这些数值属于标签语义，可以直接进入规则：

| 条件 | 数值 |
|---|---:|
| 数据断档 | 相邻采样间隔 `> 1.0 s` |
| 蹲姿保持 | 最低位停止 `>= 0.5 s` |
| 站立调整内部停止切回静止 | 停止 `>= 0.5 s` |

### 12.2 可作为搜索起点的历史经验值

下表来自仓库现有离线规则和 ADR 的历史开发经验，并非本次人工标注直接套用的阈值。它们依赖设备单位、佩戴方式和受试者，只适合做参数搜索初值：

| 特征 | 历史起点 | 适用提醒 |
|---|---:|---|
| 静止运动阈值 | 开头静止窗 `median + 8 * MAD`，并限制在约 `7.1-12.0` | 开头已在动作中时会污染标定；8.3 的 T01、T05 就不能盲用 |
| 局部运动阈值 | 约 `5.0-9.0` | 使用角速度原始单位，只能同设备比较 |
| 同腿相邻步候选最小间隔 | 约 `0.25 s` | 只是防重复峰，不代表真实步态周期 |
| 腿位峰显著度 | 约 `0.10` | 应按静止噪声和个体摆幅归一化 |
| 弯腰俯仰摆幅候选 | 约 `30°` | 已知存在弯腰与深蹲重叠的受试者 |
| 蹲起双腿原始速度相关 | 强候选约 `<= -0.7` | 负号来自通道方向，换设备后需重新确认 |
| 行走交替次数 | 连续段内至少 `3` 次 | 只建立候选，不能替代持续性和幅度检查 |
| 转身平滑 `|Gyro Y|` | 约 `25` | 强依赖坐标系和设备单位 |
| 楼梯俯仰带弱分离 | 与平地中心差 `< 3°` | 此时应提高冲击、步频和竖直加速度权重 |
| 楼梯竖直 RMS | 相对平地约 `> 1.45` | 必须用同一行走段的平地基线归一化 |
| 上下楼竖直峰不对称分界 | 约 `1.55` | 只能作为方向辅助证据 |

更可靠的阈值策略是：

- 用每个会话真实静止段估计噪声中位数和 MAD。
- 用同一受试者清晰平地步态估计腿位摆幅、步频和冲击基线。
- 使用相对倍率、分位数和持续性，而不是跨人绝对值。
- 单独保留高噪声、初始窗被动作污染和俯仰弱分离的回退路径。
- 在受试者维度划分训练、验证和测试，不能随机拆散同一人的采样点。

## 13. 推荐的状态检测结构

建议把检测器拆成以下层次：

```text
原始 CSV / 实时采样
    -> 时间与数据质量检查
    -> 坐标变换、滤波和会话内标定
    -> 腿位周期、运动强度、姿态带、冲击和竖直特征
    -> 活动候选分类
    -> 地形候选分类
    -> 合法组合约束
    -> 候选状态持续性与迟滞
    -> 确认状态和一次性切换事件
```

一个可实现的判定顺序如下：

```text
if 数据断档:
    标记不可观测，不把插值平线当成静止
elif 低位蹲姿平台持续 >= 0.5s:
    activity = SQUAT_HOLD
elif 双腿和 IMU 持续安静:
    activity = STILL
elif 蹲姿轨迹持续下降:
    activity = SQUAT_DESCENT
elif 蹲姿轨迹持续上升:
    activity = SQUAT_ASCENT
elif 双腿大幅规则交替且符合原地高抬特征:
    activity = HIGH_KNEE_ALTERNATING
elif 双腿规则交替且形成持续步态:
    activity = WALKING
elif 俯仰主导的完整前屈恢复:
    activity = BEND
elif 站立小幅、转身或拖步特征成立:
    activity = STANDING_ADJUSTMENT
elif 明确运动但无专名类别成立:
    activity = OTHER
else:
    保持上一确认状态或进入待复核候选

if 楼梯多信号证据成立:
    terrain = ASCENT or DESCENT
elif 正坡度承重面或稳态上坡证据成立:
    terrain = INCLINE
elif 已确认在平地、平台或 0° 跑带:
    terrain = LEVEL
else:
    保持上一确认地形并输出不确定证据
```

顺序不是不可变的分类器优先级。实际实现中，弯腰和蹲起、行走和高抬腿应由同一窗口的多特征模型联合打分，再由状态机施加允许的转移关系。

## 14. 训练与评估建议

- 活动和地形可以分别建模，但最终必须在组合状态层校验合法性。
- `STILL` 门控应优先保证不把动作换向点误判为静止。
- `SQUAT_*` 更适合方向状态机，不宜只训练完整动作分类器。
- `LEVEL/INCLINE` 训练使用人工复核后的 T05 有效行走数据，并排除 `0°` 启动加速、跑带与边缘之间的跨步及等待；不按固定步数、周期数或时长截取。
- 跑步机 `0°` 是设备基线，不等于自然速度真实平地；两者差异同时包含设备和速度因素。
- 当前 V2 设计不把原始前后向 `z` 加速度作为 `LEVEL/INCLINE` 的主特征。若后续加入，应单独做消融实验，不能根据本批结果直接宣称有效。
- T04 只能做留出验收，不能参与阈值选择。
- 评估时同时报告逐样本分类、区间 IoU、事件序列和边界误差；无视频近似标注不适合追求毫秒级边界复刻。
- 实时检测应报告候选状态、确认状态和确认延迟。离线标注可以回看并把边界吸附到动作真实起点，二者的时间定义不同。

## 15. 已知风险

- 无同步视频，楼梯首级、末级、跑带与边缘之间的跨步以及最终下到地面的承重转移仍是传感器近似值。
- 俯仰绝对值受穿戴姿态影响，下楼与平地有时只有很弱分离。
- 弯腰与深蹲在部分受试者上可能仅靠俯仰和腿位仍不可分，需要躯干与大腿的独立姿态或更多传感器。
- T05 角度和速度来自固定采集流程，CSV 没有设备遥测，无法仅靠文件证明具体档位。
- 原地高抬腿与低速原地步态、拖步与短距离行走之间存在天然模糊区，需要持续性、幅度和上下文共同判断。
- 本文只总结一名新受试者和历史规则经验，任何阈值都必须经过更多受试者的留出验证。

## 16. 实现前检查清单

- 是否按真实时间而不是固定采样点数计算持续时间？
- 是否先应用正确的 IMU 坐标变换？
- 是否检测开头静止窗被动作污染？
- 是否同时使用双腿交替、IMU 动态和姿态证据？
- 是否把动作换向点与真正静止区分开？
- 是否保留楼梯或坡面上的静止地形？
- 是否对候选状态使用持续性、迟滞和退出条件？
- 是否把确认事件与状态边界分开处理？
- 是否避免用协议顺序补造缺失动作？
- 是否按受试者划分训练和测试，并保持 T04 留出？
- 是否只使用人工复核后的 T05 有效行走数据，并排除启动加速、跨步和等待？
- 是否把低置信、断档和非法组合送入 QA，而不是静默改写？
