# 正式 V3 允许声明采集异常断档

## 状态

已采纳（2026-09-07）。

## 决策

正式 V3 记录允许标注员对真实采集异常断档逐项声明。每个非接缝断档必须同时保留一个阻断 QA、一个断档后的首个真实采样点重新确认标记（或复用该点的普通状态边界）以及配套报告中的结构化声明；QA 只有填写非空判断依据并选择“确认无需修改”后才算闭环。重新确认不改变活动或地形状态，固定在断档后的首个真实采样点，断档内部不推断边界。

T04 `v3_1+2` 继续只允许一个 `3.000 s ± 0.001 s` 的接缝断档，并使用固定的 `stitch_initial` 事件；其他断档按采集异常流程逐项处理。T04 `_1`、`_2` 源记录仍为只读。标注 CSV 继续保持既有七列，声明信息写入 QA、事件备注和配套报告；原始 CSV、统计扣除断档时长的行为以及训练/验证接口均不改变。

## 原因与后果

真实采集异常不应迫使标注员伪造连续传感器证据或修改原始数据，同时也不能让断档被默认为静止或状态边界。将 QA、重新确认和报告绑定，既允许正式保存，也让每个断档的原因、判断依据和状态复核可追溯。自动识别、人工空文档和恢复草稿使用同一幂等物化规则，避免重复生成 QA 或标记。

## 旧草稿兼容

旧草稿兼容：仅当旧版“V3 正式/源文件存在未声明数据断档”汇总 QA 已附非空理由确认无需修改、且唯一对应一个数据断档时，允许将结论迁移到尚未处理的逐区间 QA 和断档后确认备注。配套报告保留原 QA 与目标区间的迁移记录；多个断档仍需逐项确认，不从汇总理由推断各断档结论，也不覆盖已有逐区间结论。

## 不采用的方案

- 不插值、补写或修改原始传感器 CSV。
- 不把断档直接降级为提示、不以一句试次级备注替代逐断档 QA。
- 不新增 CSV 字段，也不把断档内部的推断边界写入标注事件。
